# 数据库性能优化指南

## 概述

本文档提供Smart Doctor项目的数据库性能优化方案，包括SQLite到PostgreSQL的迁移指南、性能调优配置和最佳实践。

## 1. 数据库迁移方案

### 1.1 当前状态
- **开发环境**: SQLite3
- **生产环境**: PostgreSQL 15.x
- **缓存数据库**: Redis 7.x

### 1.2 迁移步骤

#### 步骤1: 安装PostgreSQL
```bash
# Windows (使用Chocolatey)
choco install postgresql15

# 或者下载PostgreSQL安装包
# https://www.postgresql.org/download/windows/
```

#### 步骤2: 配置PostgreSQL
```sql
-- 创建数据库和用户
CREATE DATABASE smart_doctor;
CREATE USER smart_doctor_user WITH PASSWORD 'your_secure_password';
GRANT ALL PRIVILEGES ON DATABASE smart_doctor TO smart_doctor_user;

-- 优化数据库配置
ALTER DATABASE smart_doctor SET shared_preload_libraries = 'pg_stat_statements';
ALTER DATABASE smart_doctor SET log_min_duration_statement = 1000;
```

#### 步骤3: 执行迁移脚本
```bash
# 设置生产环境变量
cp .env.production .env

# 编辑.env文件，配置数据库连接参数
# 然后运行迁移脚本
python postgresql_setup.py
```

## 2. 性能优化配置

### 2.1 Django数据库配置优化

#### 连接池配置
```python
# settings.py中的优化配置
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'CONN_MAX_AGE': 600,  # 连接池保持时间
        'OPTIONS': {
            'connect_timeout': 10,
            'keepalives': 1,
            'keepalives_idle': 30,
            'keepalives_interval': 10,
            'keepalives_count': 5,
        }
    }
}
```

#### 查询优化
```python
# 使用select_related和prefetch_related优化关联查询
hospitals = Hospital.objects.select_related('location').prefetch_related('doctors').all()

# 使用only和defer控制字段加载
doctors = Doctor.objects.only('name', 'specialty', 'hospital').all()
```

### 2.2 PostgreSQL性能调优

#### postgresql.conf优化
```ini
# 内存配置
shared_buffers = 256MB          # 25% of RAM
work_mem = 4MB                  # 每个查询的工作内存
effective_cache_size = 1GB       # 75% of RAM

# 连接配置
max_connections = 100

# 日志配置
log_destination = 'stderr'
logging_collector = on
log_directory = 'pg_log'
log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
log_min_duration_statement = 1000

# 自动清理
autovacuum = on
autovacuum_vacuum_scale_factor = 0.1
autovacuum_analyze_scale_factor = 0.05
```

#### 索引优化
```sql
-- 为常用查询字段创建索引
CREATE INDEX idx_hospitals_location ON hospitals(location_id);
CREATE INDEX idx_doctors_hospital ON doctors(hospital_id);
CREATE INDEX idx_appointments_user ON appointments(user_id);
CREATE INDEX idx_appointments_doctor ON appointments(doctor_id);

-- 复合索引
CREATE INDEX idx_doctors_specialty_hospital ON doctors(specialty, hospital_id);
CREATE INDEX idx_appointments_status_date ON appointments(status, appointment_date);
```

## 3. 缓存策略

### 3.1 Redis缓存配置
```python
# settings.py
CACHES = {
    'default': {
        'BACKEND': 'django_redis.cache.RedisCache',
        'LOCATION': 'redis://127.0.0.1:6379/1',
        'OPTIONS': {

            'SOCKET_TIMEOUT': 5,
            'COMPRESSOR': 'django_redis.compressors.zlib.ZlibCompressor',
        }
    }
}

# 缓存超时配置
CACHE_TTL = 60 * 15  # 15分钟
```

### 3.2 缓存使用模式
```python
from django.core.cache import cache

# 缓存医院数据
@cache_page(60 * 15)  # 缓存15分钟
def hospital_list(request):
    hospitals = cache.get('all_hospitals')
    if not hospitals:
        hospitals = Hospital.objects.select_related('location').all()
        cache.set('all_hospitals', hospitals, 60 * 15)
    return hospitals

# 缓存医生推荐结果
def get_recommended_doctors(user_id):
    cache_key = f'recommended_doctors_{user_id}'
    doctors = cache.get(cache_key)
    if not doctors:
        doctors = RecommendationEngine.get_recommendations(user_id)
        cache.set(cache_key, doctors, 60 * 5)  # 缓存5分钟
    return doctors
```

#### PostgreSQL监控
```sql
-- 查看慢查询
SELECT query, calls, total_time, mean_time 
FROM pg_stat_statements 
ORDER BY mean_time DESC 
LIMIT 10;

-- 查看表大小和索引使用情况
SELECT schemaname, tablename, 
       pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) as size,
       n_live_tup as rows
FROM pg_tables 
WHERE schemaname NOT IN ('information_schema', 'pg_catalog')
ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;
```

### 4.2 性能诊断脚本
```python
# performance_monitor.py
import time
from django.db import connection
from django.core.cache import cache

def query_performance():
    """查询性能监控"""
    start_time = time.time()
    
    # 执行查询
    hospitals = Hospital.objects.all()
    
    end_time = time.time()
    execution_time = end_time - start_time
    
    # 获取查询详情
    queries = connection.queries
    
    return {
        'execution_time': execution_time,
        'query_count': len(queries),
        'queries': queries
    }

def cache_performance():
    """缓存性能测试"""
    # 测试缓存读写性能
    test_data = {'test': 'performance'}
    
    # 写入测试
    start_time = time.time()
    cache.set('performance_test', test_data, 60)
    write_time = time.time() - start_time
    
    # 读取测试
    start_time = time.time()
    cached_data = cache.get('performance_test')
    read_time = time.time() - start_time
    
    return {
        'write_time': write_time,
        'read_time': read_time,
        'data_valid': cached_data == test_data
    }
```

## 5. 最佳实践

### 5.1 数据库设计最佳实践

1. **规范化设计**: 遵循数据库规范化原则
2. **适当反规范化**: 对频繁查询的表进行适当反规范化
3. **合理使用索引**: 为查询条件字段创建索引
4. **分区策略**: 对大表考虑分区策略

### 5.2 查询优化最佳实践

1. **避免N+1查询**: 使用select_related和prefetch_related
2. **批量操作**: 使用bulk_create、bulk_update
3. **延迟加载**: 使用only和defer控制字段加载
4. **查询分析**: 使用explain分析查询计划

### 5.3 缓存策略最佳实践

1. **分层缓存**: 使用多级缓存策略
2. **缓存失效**: 合理设置缓存过期时间
3. **缓存预热**: 系统启动时预热常用数据
4. **监控缓存命中率**: 监控缓存使用效果
